# 帆船海洋美术与生成模块

## 直接运行

仓库目标版本为 Unity **6000.6.1f1**。交付包已在该版本导出并在干净工程中验证场景引用；Windows 演示需使用完整安装的同版本 Windows Standalone Build Support 构建。

打开 `Assets/SailingOut/Generated/Demo/SailingOutGenerationDemo.unity`，点击 Play；在开始界面点击 **START SAILING** 后开始航行。演示默认自动沿安全通道航行，便于观察全部难度阶段。点击 Game 窗口后：

当前基础航速和横向操控速度较之前提高约 20%；闪电加速仍为每局三次、每次 3 秒。

| 操作 | 效果 |
| --- | --- |
| A / D 或左右方向键 | 手动横向操船，并关闭自动导航 |
| Space | 切换自动导航 |
| W | 消耗一次闪电次数，加速 3 秒；拾取河道中的绿色闪电可补充次数，上限三次 |
| R | 用相同种子从起点重来 |
| N | 换下一个种子从起点重来 |
| F1 | 显示种子、活动对象和池内对象数量 |

在仓库根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\Build-Delivery.ps1`，即可生成同一场景的 `Builds/SailingOutDemo/SailingOutDemo.exe`。`Builds/` 不随 Git 提交；运行演示时保留整个文件夹。主角船仅为演示配套资源，正式移动、收集、伤害、加速和追逐由其他成员接入。

## 导入另一工程

在干净 Unity 6 工程中，使用 **Assets > Import Package > Custom Package** 导入 `Delivery/SailingOut-ArtGeneration.unitypackage`，保留全部文件，然后打开上述演示场景。包内脚本在 `Assets/SailingOut/Module` 下，引用 GUID 与本工程一致，不要求新 Input System，也不需要改 TagManager。

本工程已经使用 `Packages/com.sailingout.art-generation` 嵌入式包，**不要再把交付 unitypackage 导回本工程**，否则会出现同名程序集。两个分发方式选择一个即可。Prefab 使用默认层承载实体/Trigger，用内置 Ignore Raycast 层承载纯装饰；通过 `SpawnableIdentity.Definition.Category` 区分具体类别，不依赖工程私有 Tag。

## 主工程接入

给空物体添加 SpawnManager，赋值 Profile、正交 Camera、主角 Collider2D；`Initialize On Start` 勾选时会自动启动和跟随生成/回收。若由主程负责生命周期，关闭该选项：

```csharp
spawnManager.Configure(profile, camera, boatCollider, automatic: false);
spawnManager.Initialize(seed);
// automatic 为 false 时，由主程在 Update 内按顺序调用。
spawnManager.RecycleBehind(playerY);
spawnManager.EnsureAhead(playerY, playerX);
// 结束/重新开始可清场
spawnManager.ClearAndReturnToPool();
```

`Configure(..., automatic: false)` 关闭自动初始化和自动维护，主程可以按暂停/运行状态调用位置接口。正式接入优先传真实碰撞体；传 null 时船尺寸回退为 1×2 世界单位。ClearAndReturnToPool 会停止本局维护，重新开始需再次 Initialize。不要同时给同一个场景放置多个生成器。

Initialize 会固定本局的视口宽度、段长、船宽与船长。保持正交相机缩放、横向中心和船 Collider 尺寸不变；纵向跟随可正常移动。重播需要同一种子、相同起点/相机/碰撞尺寸、相同配置与定义顺序。playerX 接口保留给调用方；航路不随着船横向移动而重新生成。仅支持持续 +Y；倒退不会补生成旧段。

生成器只激活、定位、复用和回收对象。补给收集时由外部代码执行奖励并隐藏对象，等越过回收线后进入对象池；请不要 Destroy 池管理的对象。对象根节点实现 `IPooledSpawnable` 即可在 OnSpawned/OnDespawned 重置自己的临时状态。默认动画会重新绑定到第一帧。

## 随机规则和配置

- 默认段长 2 屏、前方 2.5 屏、后方 1.5 屏；还保证相机顶部之外至少半屏已生成。
- 每段使用独立整数随机数，输入为种子和世界航段编号。连续坐标采样，无槽位。
- 边界为每个对象半径外再保留半个全局最大间距，使相邻航段互不依赖回收时机。段内使用所有已放置圆形包围边界做间距检查，包含透明边缘和额外缓冲，宁可保守跳过。
- clearanceRadius 必须包围所有外观和动画帧；Collision Boundary Padding 是额外留白。若更换大图或扩大 Collider，应同时调大边界。
- 安全通道宽度至少为真实船宽 + 两侧缓冲，弯道检查还包含船长。通道中心在每 3 段之间平滑插值。礁石完整留在通道外，补给和闪电优先通道内部；浮标、补给和闪电使用 Trigger Collider，海鸟、碎片没有 Collider。收集补给会恢复半颗心，最多三颗；满血时不增加生命，但补给仍会消失。按 W 可消耗一次闪电进行 3 秒的 2 倍加速；河道中的绿色闪电可补充一次，最多持有三次，满额拾取也会消失。剩余次数显示为右上角绿色闪电。演示船碰到浮标后会以半速航行 0.5 秒，并随机向左或向右挤开；浮标和礁石各会扣除半颗心，每局初始三颗心显示在左上角。生命值归零后会停止航行，并显示全屏红色死亡界面和重开按钮。
- 无效候选最多尝试 28 次；过密时减少实际数量，不强行塞入。所有类别都做最小间距检查。
- 阶段起点默认 0、120、300、600 世界单位。第一阶段没有礁石和补给，第二阶段每段目标 1～2 个补给；第三阶段混合，第四阶段礁石加密。数量表示尝试目标，空间不足时可能不足。
- Obstacle Density By Distance 曲线控制礁石随距离增长的倍率；非礁石仍使用各阶段数量范围。
- Max Active Objects / Max Pooled Objects 默认各 256，避免无限增长。若人为调低活动上限导致截断，重播还需相同的逐帧调用节奏；默认配置远低于上限。

## 美术制作和替换

当前素材是本项目直接绘制的原创像素图，由用户选择采用；没有使用 Edge 美术，也没有把程序绘图冒充 AI 输出。后续 AI 草图提示词见 `Art/AI_PROMPTS.md`。

1. 按 `美术规范.md` 确定轮廓和尺寸；对象帧为 32×32，透明留白允许，动画各帧尺寸相同。
2. AI 草图或人工稿先压缩颜色、擦掉半透明边缘，再按像素网格修正轮廓和统一左上光照。
3. 覆盖对应 `类别_外观_帧.png` 时保留 `.meta`，并同步更新 SpriteSheets。图集是交付源图，运行动画引用独立 PNG 帧。
4. 使用 **Sailing Out > Rebuild Included Demo** 重建动画、Prefab 和配置。重建会恢复生成器默认参数；调好的自定义 Profile 建议另存为新资产。
5. 在 1920×1080 Game 窗口检查。演示内部以 384×216 渲染、Point 整数放大，1080p 恰好 5 倍；非整数分辨率会留黑边以保持边缘清晰。

**Create Missing Original Pixel Art** 只创建缺失的源 PNG，不覆盖已有美术编辑；**Apply Pixel Settings to Selected Textures** 可修复单张贴图设置。默认构建器会按当前源帧和纹理重建完整演示。

## 测试和复现

Unity Test Runner 的 PlayMode 覆盖种子、通道、跨段间距、传送/回收节奏、池上限以及 600 秒 × 60 步的模拟航行；EditMode 检查交付资产和实际进入 Play 的动画重置。测试程序集在嵌入包里，工程 manifest 已加入 testables。

在 Windows 演示中加 `-sailingoutSoak 输出目录` 可进行 605 秒实际运行检查，自动保存两张画面和帧率/对象数量报告。正常运行不启用测试采集。最终实测证据见交付测试说明。
